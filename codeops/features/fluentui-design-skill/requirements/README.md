## Overview

`fluentui-design` produces an installable **Agent Skill** that helps a coding agent make defensible
UI/UX decisions and implement them correctly with **Fluent UI React v9**. The central problem is
**application composition**: how navigation, page headings, commands, forms, data grids, tabs,
dialogs, drawers, collapsible sections, and feedback fit together into usable screens and workflows.

The skill is a **separate, complementary** artifact to the API-focused `fluentui` skill generated by
the sibling `fluentui-mcp` repository. This project owns the sourced design/composition layer:
traceable rules, application patterns, evidence, and a runnable fixture that proves the examples.
It consumes the sibling skill's pinned component facts instead of re-scraping them.

Every non-obvious claim in the skill traces to a reviewed source (Fluent 2 guidance, version-matched
v9 facts, WCAG 2.2, WAI-ARIA APG, official Microsoft product patterns, or a visibly labeled derived
recommendation). The skill is usable offline from its bundled references.

## Minimum-Sufficient Baseline

**Original goal:** Turn the master brief into an evidence-backed Agent Skill for Fluent UI React v9
application composition, with verified examples and an evaluation of its usefulness.

**Smallest viable design:** A curated Markdown skill (`SKILL.md` + topic references) backed by a
source catalog and rules catalog in JSON, with typecheck-verified examples.

**Excluded support machinery:** No external database or hosted service; no runtime server or MCP
proxy; no vector store; no model-provider dependency for the default evaluation path; no automated
skill-vs-baseline agent comparison unless a provider is later authorized.

**Approved complexity:** AR #2 (Complexity Escalation) — a runnable Vite + React + TypeScript
fixture app with an npm lockfile, Playwright + axe-core browser/accessibility evidence, JSON Schema
validators plus a deterministic generator, and a lightweight evaluation (tasks + rubric + actual
results). Independently challenged and returned `Justified`.

## Domain Glossary

| Term | Definition |
|------|-----------|
| Agent Skill | A portable capability package defined by the Agent Skills standard: a `SKILL.md` entry point plus progressive-disclosure references, assets, and optional scripts. |
| Runtime code | The browser code a user of the skill writes (application code). |
| Tooling code | The scripts in this repository that build, validate, and evaluate the skill. |
| Source catalog | The canonical JSON inventory of reviewed evidence sources (`sources/sources.json`). |
| Coverage matrix | The mapping from in-scope topics to sources, evidence, rules, examples, and gaps. |
| Rule | A conditional, decision-bearing instruction with a stable ID, applicability, evidence, and verification. |
| Application pattern | A documented, application-owned composition (for example AppShell or FilterBar) that is not a verified library export. |
| Surface | A place UI work is presented: main page, inline edit, drawer, or dialog. |
| Derived recommendation | Guidance this project synthesized rather than sourced; always visibly labeled. |
| Fixture app | The runnable TypeScript application that validates the patterns and examples. |
| Seed ID | A source identifier from the master brief's initial catalog (for example `F01`), retained as an alias. |

## Key Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Relationship to the sibling API skill | Separate skill that consumes pinned facts | Different content type, oracle, cadence, and routing; the sibling forbids hand-edited generated output (AR #4, #12). |
| Catalog storage | JSON canonical + JSON Schema + deterministic generator | Verifiable, diffable, no database service (AR #10, #3). |
| Facts source | Pinned snapshot of the sibling enhanced schema | Grounds API names/props without re-scraping or duplication (AR #8, #12). |
| Evidence retention | Original summaries + links + locators | Respects source terms; no wholesale copies (AR #5). |
| Fixture stack | Vite + React 18 + TypeScript + npm | Smallest mainstream stack for a runnable, typecheckable fixture (AR #2, #19). |
| Browser/a11y evidence | Playwright + axe-core | Required for focus, reflow, and automated accessibility evidence (AR #2). |
| Example discipline | App compositions are application-owned unless a v9 export is verified | Prevents invented APIs presented as library components (brief section 6). |

## How to Use These Documents

Each requirements document is used with the `make-plan` skill:

1. Pick a requirements document (for example RD-01).
2. Run the `make-plan` skill against it.
3. The plan declares `Implements: fluentui-design-skill/RD-01` and derives specs and tasks.
4. Run `exec-plan` to implement and verify iteratively.
